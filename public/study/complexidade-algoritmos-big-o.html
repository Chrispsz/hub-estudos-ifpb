Complexidade de algoritmos: o que a notação O grande mede

A notação O grande compara o custo de um algoritmo com uma função do tamanho da entrada n. Uma busca linear faz até n comparações; uma busca binária faz no máximo 20 em 1.048.576 itens ordenados. Esta página define O, Θ e Ω, traça as duas buscas com valores reais e mostra o que a classe de crescimento esconde.

Definição: limite superior assintótico

Dizemos que f(n) = O(g(n)) quando existem constantes c > 0 e n₀ tais que 0 ≤ f(n) ≤ c·g(n) para todo n ≥ n₀ [Cap. 3]. A notação Θ aperta dos dois lados, com c₁·g(n) ≤ f(n) ≤ c₂·g(n), e a notação Ω registra o limite inferior; esses papéis foram fixados por Knuth para eliminar a mistura de usos do símbolo O [SIGACT News, 1976].

A afirmação f(n) = O(g(n)) compara taxas de crescimento: para n grande, g(n) vezes uma constante serve de teto para f(n).

Traço da busca linear: o vetor A = [3, 7, 11, 15, 19, 23, 27, 31] tem n = 8; para o alvo 19 as comparações caem em 3, 7, 11, 15 e 19, cinco comparações. Para um alvo ausente o laço percorre os 8 elementos. No pior caso o custo é n comparações, e a busca linear é O(n) [Seção 1.4].

Trocar de computador altera o tempo em segundos e mantém a taxa: um hardware 10× mais rápido continua executando até n comparações no pior caso, e a classe segue O(n) [Seção 1.4].

Busca binária: 20 comparações em 1.048.576 itens

Com o vetor ordenado, a busca binária compara o alvo com o elemento central e descarta uma metade a cada passo [Aula 3].

Traço: alvo 613.511 em n = 1.048.576. O primeiro centro é 524.288; o alvo é maior, o intervalo passa a [524.289, 1.048.576]. O segundo centro é 786.432; o alvo é menor, o intervalo passa a [524.289, 786.431]. Cada passo divide o tamanho por 2, e o número de passos até o intervalo de tamanho 1 é log₂ 1.048.576 = 20 [Seção 1.4].

O teto de comparações é ⌈log₂ n⌉: cada passo divide o intervalo por 2.

O requisito de ordenação é o caso de falha: ordenar custa O(n log n), e para uma única consulta em vetor desordenado a busca linear O(n) custa menos [Seção 1.4].

Constantes ocultas: o que a classe esconde

A definição descarta constantes multiplicativas e termos de baixa ordem: 3n² + 100n + 7 = O(n²) [Cap. 3]. Dois algoritmos da mesma classe podem diferir por um fator de 10 ou mais no tempo medido, e a análise detalhada de constantes faz parte da comparação prática [Seção 1.4].

O sort padrão do Python, o Timsort, usa insertion sort binário em sequências de até 64 elementos; a constante aparece no código-fonte como #define MAX_MINRUN 64 [listobject.c, linha 1789].

MAX_MINRUN = 64 marca a troca: acima desse tamanho, o Timsort deixa o insertion sort pelo merge.

Traço do bloco de 64: o insertion sort no pior caso faz 64·63/2 = 2.016 comparações; o mergesort faz 64·log₂ 64 = 384 comparações, mais buffer de merge e chamadas recursivas. As 2.016 comparações simples rodam sem alocação extra, e por isso o código de produção adota o algoritmo de classe O(n²) dentro do bloco [comentários de listobject.c].

O que esta página não mostra

Separar caso médio de pior caso: o quicksort tem O(n log n) no caso médio e O(n²) no pior, controlado pela escolha do pivô [Cap. 3]. Análise amortizada: o push de um array dinâmico custa O(1) amortizado com dobra de capacidade [Seção 1.4]. Complexidade de espaço, comportamento de cache de CPU, paralelismo e custo de I/O ficam de fora. Conceitos deixados de fora por falta de orçamento: a notação o minúsculo, recorrências com o teorema mestre e a relação entre classes de complexidade e computabilidade.
